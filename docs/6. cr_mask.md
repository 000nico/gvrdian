while we are in VMX operations, the CPU needs some bits to be set in CR0 and CR4. for example
CR3.VMXE (bit 13) = 1

if guest executes mov rax, cr4 and reads that bit, it will know that there is a hypervisor present, we need the guest reading a different control register, a shadow register

the mecanism: four camps of vmcs
CR0_GUEST_HOST_MASK (0x6000) -> bits that hypervisor "has": in CR0
CR0_READ_SHADOW     (0x6004) -> bits that guest see in CR0
CR4_GUEST_HOST_MASK (0x6002) -> bits that hypervisor "has" in CR4
CR4_READ_SHADOW     (0x6006) -> bits that guest see in CR4

the rule is: if in the mask the bit is 1, the guest reads the shadow bit instead of the real bit, if in the mask that bit is 0, the guest reads the real control register

what happens when guest tries to write in CR0
example with bit 13:
    guest executes MOV CR4, RAX. 

    cpu compares:
        RAX and SHADOW 
        if user trying to write bit 13 (vmxe) && actual shadow says vmxe = 0
            if bit 13 of new value == bit 13 of shadow -> no vmexit
            if bit 13 of new value !- bit 13 of shadow -> vmexit reason 28


basically 
    if (shadow & mask) != (mask & rax)
        vmexit 28

or, if there is a diff between our shadow (if the mask is set in that bit) and what the user wants to write on.
